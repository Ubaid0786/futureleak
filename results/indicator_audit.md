### Causes

**ta 0.11.0 `trend.KSTIndicator`** (undocumented leak)

- Call: `ta.trend.KSTIndicator(close)`
- Measured: kst, kst_diff, kst_sig: full_sample, horizon >=440 (to end of data), 100% of cuts; only rows up to position 51 are affected
- Cause: Each rate of change is computed against close.shift(r, fill_value=close.mean()), so the first r rows are compared with the mean of the whole series, future included. With the default windows the contaminated values are KST rows 14-43 and signal rows 14-51 (the first 14 rows are missing); later rows are clean.
- Source: `ta/trend.py:500-535`
- Documentation: Not mentioned in the class docstring (ta/trend.py:440-462). The same fill was reported for the daily-return indicator (bukosabino/ta issue 323) and removed there (pull request 324, merged 2023-10-29); the KST lines are unchanged on the master branch as of 2026-11-15.

**finta 1.3 `ICHIMOKU`** (leaks by design, not documented)

- Call: `finta.TA.ICHIMOKU(ohlcv)`
- Measured: CHIKOU: fixed_horizon, horizon 26, 100% of cuts
- Cause: The Chikou span is ohlc['close'].shift(-chikou_period): the value at row t is the close 26 rows later. This is the standard definition of the span, which is drawn 26 bars behind price on a chart.
- Source: `finta/finta.py:1897-1900`
- Documentation: The docstring (finta/finta.py:1857-1862) does not say that the column holds future closes.

**finta 1.3 `QSTICK`** (output depends on input length, no future values read)

- Call: `finta.TA.QSTICK(ohlcv)`
- Measured: 14 period QSTICK.: truncation_only, horizon -, 100% of cuts
- Cause: The function takes ohlc['close'].tail(period) and ohlc['open'].tail(period) and returns (close - open) / period for those rows only. It is not a rolling average: the output exists for the last 14 rows of whatever frame is passed, so the value at row t depends on how many rows follow it. The values themselves use only the row's own open and close.
- Source: `finta/finta.py:1775-1780`
- Documentation: The docstring (finta/finta.py:1771-1773) describes an average over the past N days.

**finta 1.3 `SAR`** (undocumented leak)

- Call: `finta.TA.SAR(ohlcv)`
- Measured: value: full_sample, horizon >=440 (to end of data), 100% of cuts; only rows up to position 88 are affected; audited on an integer index (on the date index: KeyError: 0)
- Cause: The recursion is seeded with low[0] - (high - low).std(), the standard deviation of the bar range over the whole series. The seed enters each later value through the recursion. The dependence ends once the path has reversed and resynchronised: a reversal sets the value to the running extreme, which does not involve the seed. Only observable on an integer index: on a date index the function raises KeyError under pandas 3.1 because of high[0].
- Source: `finta/finta.py:829`
- Documentation: Not mentioned in the docstring (finta/finta.py:822-824).

**finta 1.3 `STOCHRSI`** (undocumented leak)

- Call: `finta.TA.STOCHRSI(ohlcv)`
- Measured: 14 period stochastic RSI.: full_sample, horizon >=440 (to end of data), 60% of cuts
- Cause: RSI is scaled as (rsi - rsi.min()) / (rsi.max() - rsi.min()) with the minimum and maximum of the whole series, not of the trailing stoch_period window, and then smoothed. Every value changes whenever a later RSI sets a new extreme.
- Source: `finta/finta.py:1237`
- Documentation: The docstring (finta/finta.py:1231-1233) describes the range 'over a set time period'.

**finta 1.3 `WILLIAMS_FRACTAL`** (leaks by design, documented)

- Call: `finta.TA.WILLIAMS_FRACTAL(ohlcv)`
- Measured: BearishFractal, BullishFractal: variable_horizon, horizon 1..2, 100% of cuts
- Cause: Both outputs use rolling(window=2 * period + 1, center=True), so the flag at row t reads period = 2 rows after t. A fractal is defined by the bars on both sides of it.
- Source: `finta/finta.py:2227, 2233`
- Documentation: finta/finta.py:2211: period is 'how many lower highs/higher lows the extremum value should be preceded and followed'.

**pandas_ta_classic 0.9.0 `overlap.ichimoku`** (leaks by design, documented)

- Call: `pandas_ta_classic.ichimoku(high, low, close)`
- Measured: ICS_26: fixed_horizon, horizon 26, 100% of cuts
- Cause: chikou_span = close.shift(-kijun); include_chikou defaults to True.
- Source: `pandas_ta_classic/overlap/ichimoku.py:57`
- Documentation: pandas_ta_classic/overlap/ichimoku.py:146-148 and 156-157: 'Not causal: the chikou span is close.shift(-kijun), a later bar's close'; lookahead=False drops the column.

**pandas_ta_classic 0.9.0 `statistics.tos_stdevall`** (leaks by design, documented)

- Call: `pandas_ta_classic.tos_stdevall(close)`
- Measured: TOS_STDEVALL_LR, TOS_STDEVALL_L_1, TOS_STDEVALL_U_1, TOS_STDEVALL_L_2, TOS_STDEVALL_U_2, TOS_STDEVALL_L_3, TOS_STDEVALL_U_3: full_sample, horizon >=440 (to end of data), 100% of cuts
- Cause: One regression line (np.polyfit) and one standard deviation are fitted over the whole series and returned for every row.
- Source: `pandas_ta_classic/statistics/tos_stdevall.py:72-74`
- Documentation: pandas_ta_classic/statistics/tos_stdevall.py:102-109: 'Not causal. A single linear regression is fitted over the whole window'; lookahead=False returns None with a warning.

**pandas_ta_classic 0.9.0 `trend.dpo`** (leaks by design, documented)

- Call: `pandas_ta_classic.dpo(close)`
- Measured: DPO_20: fixed_horizon, horizon 11, 100% of cuts
- Cause: With centered=True (the default) the result is (close.shift(t) - sma).shift(-t) with t = int(0.5 * length) + 1 = 11, so the value at row t uses the moving average ending 11 rows later.
- Source: `pandas_ta_classic/trend/dpo.py:39`
- Documentation: pandas_ta_classic/trend/dpo.py:76-78 and 82-84: 'Not causal: the value at a bar uses the SMA ending int(0.5 * length) + 1 bars later'; lookahead=False turns centring off.

**btalib 1.0.0 `ht_trendmode`** (undocumented leak)

- Call: `btalib.ht_trendmode(ohlcv).df`
- Measured: trendline: variable_horizon, horizon 1..6, 100% of cuts; audited on an integer index (on the date index: KeyError: 31)
- Cause: Index handling. The working series passed to _periodize have their first 6 rows removed, so on an integer index their labels start at 6. Scalar reads and writes such as price[i] and trendbuf[i] = trend are then label-based, while the trendline sum price0[i - (dcperiod - 1):i + 1] is a positional slice that ends 6 rows later. The trend flag written at label i therefore depends on prices up to row i + 6, and the last 6 rows are never written. Only observable on an integer index: on a date index the function raises KeyError under pandas 3.1.
- Source: `btalib/indicators/ht_trendmode.py:165 (positional slice) against 62, 137, 192 and 195 (label-based access)`
- Documentation: Not documented; the code is written as if all access were positional.

**ta 0.11.0 `momentum.KAMAIndicator`** (undocumented leak)

- Call: `ta.momentum.KAMAIndicator(close, fillna=True)`
- Measured: kama: full_sample, horizon >=440 (to end of data), 100% of cuts
- Cause: The volatility and efficiency-ratio terms use np.roll, which wraps around: the first rows are differenced against the last rows of the series. With fillna=False the affected rows are masked (the rolling sum has min_periods=window and the first valid KAMA value is set to the close). With fillna=True min_periods is 0, the wrapped values enter the smoothing constant of rows 1-9, and the recursion carries the error forward with decaying size.
- Source: `ta/momentum.py:319-323`
- Documentation: Not documented. Reported upstream in 2020 (bukosabino/ta issue 181, still open).

**ta 0.11.0 `trend.DPOIndicator`** (undocumented leak)

- Call: `ta.trend.DPOIndicator(close, fillna=True)`
- Measured: dpo: full_sample, horizon >=440 (to end of data), 100% of cuts; only rows up to position 10 are affected
- Cause: close.shift(11, fill_value=close.mean()) puts the mean of the whole series in the first 11 rows. With fillna=False those rows are missing because the moving average has min_periods=window; with fillna=True min_periods is 0 and rows 0-10 are returned.
- Source: `ta/trend.py:596-602`
- Documentation: Not documented.

**ta 0.11.0 `trend.KSTIndicator`** (undocumented leak)

- Call: `ta.trend.KSTIndicator(close, fillna=True)`
- Measured: kst, kst_diff, kst_sig: full_sample, horizon >=440 (to end of data), 100% of cuts; only rows up to position 51 are affected
- Cause: Same cause as with the default: close.shift(r, fill_value=close.mean()). With fillna=True the rolling means have min_periods=0, so the contaminated values start at row 0.
- Source: `ta/trend.py:492-535`
- Documentation: Not documented.

**ta 0.11.0 `trend.TRIXIndicator`** (undocumented leak)

- Call: `ta.trend.TRIXIndicator(close, fillna=True)`
- Measured: trix: full_sample, horizon >=440 (to end of data), 100% of cuts; only rows up to position 0 are affected
- Cause: ema3.shift(1, fill_value=ema3.mean()) puts the mean of the whole triple-smoothed series in row 0. With fillna=False row 0 is missing; with fillna=True the moving averages have min_periods=0 and row 0 is returned.
- Source: `ta/trend.py:273-275`
- Documentation: Not documented.

**ta 0.11.0 `trend.VortexIndicator`** (undocumented leak)

- Call: `ta.trend.VortexIndicator(high, low, close, fillna=True)`

- Cause: The true range of row 0 is computed against close.shift(1, fill_value=close.mean()). With fillna=False the first 14 rows are missing and row 0 never enters a returned value; with fillna=True the rolling sums have min_periods=0 and rows 0-13 include it.
